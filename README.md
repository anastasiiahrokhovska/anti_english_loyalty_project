# ANEI ENGLISH — Loyalty Card Bot & WebApp

Цей проєкт містить повністю готовий код Telegram WebApp з інтерфейсом картки лояльності та бота на Python (`aiogram 3`).

## Структура проекту:
- `index.html` — Веб-сторінка картки (Web App) для Telegram.
- `bot.py` — Телеграм-бот для обробки бронювань, видачі штампів та масових розсилок.
- `requirements.txt` — Список потрібних Python-бібліотек.

## Як запустити у PyCharm:
1. Розархівуйте ZIP-файл та відкрийте папку через **PyCharm**.
2. Встановіть залежності у терміналі PyCharm:
   ```bash
   pip install -r requirements.txt
   ```
3. Відкрийте `bot.py` і вкажіть свої дані:
   - `BOT_TOKEN` — Токен бота від @BotFather
   - `ADMIN_ID` — Ваш Telegram ID (можна дізнатися через @userinfobot)
   - `WEB_APP_URL` — Посилання на розгорнутий `index.html` (наприклад, з GitHub Pages).
4. Запустіть файл `bot.py`.

## Особисті кабінети каналів — налаштування перед запуском

У `index.html` додано вхід за ніком каналу й паролем через Firebase Authentication. Для роботи потрібно виконати налаштування у Firebase Console — одного коміту в GitHub недостатньо.

### 1. Увімкніть Firebase Authentication
1. Відкрийте Firebase Console і виберіть проєкт `aneienglishloyaltyproject`.
2. Перейдіть до **Authentication → Sign-in method**.
3. Увімкніть **Email/Password**.

Для сумісності з входом за ніком застосовується технічний email: `нік-каналу@channels.aneienglish.com`. Це не має бути справжня поштова скринька.

### 2. Створіть акаунт для кожного каналу
Для кожного з приблизно 40 каналів:
1. Нормалізуйте нік так само, як у формі входу: приберіть початковий `@`, переведіть у нижній регістр, а символи поза `a-z 0-9 . _ -` замініть дефісом.
2. У **Authentication → Users → Add user** створіть користувача з технічним email і згенерованим унікальним паролем.
3. Збережіть нік, пароль і UID користувача у безпечному місці та передайте пароль власнику відповідного каналу приватно. Не зберігайте список паролів у репозиторії.
4. Перейдіть до Realtime Database і створіть `channel_accounts/UID_КОРИСТУВАЧА` з полями, наприклад:
   ```json
   {
     "channel": "@example_channel",
     "stamps": 3,
     "participations": 3,
     "freeRewardAvailable": false
   }
   ```
   Замініть UID на справжній UID з Authentication, нік — на правильний, а кількість штампів — на підтверджену історію участей.

### 3. Застосуйте правила Realtime Database
У файлі `database.rules.json` є стартові правила: користувач може читати тільки власний профіль, а запис у профілі з браузера заборонений. У Firebase Console відкрийте **Realtime Database → Rules**, перенесіть правила з файлу й опублікуйте їх.

**Важливо:** ці правила залишають запис у `taken_topics` доступним будь-якому автентифікованому акаунту, щоб поточне бронювання продовжувало працювати. Для повністю захищеного бронювання потрібен серверний endpoint / Cloud Function, який перевіряє доступність теми й атомарно бронює її. Не вважайте поточний механізм захистом від навмисних подвійних бронювань.

### 4. Перенесіть наявні канали
Для кожного каналу вручну підтвердьте кількість уже зарахованих участей за своїми записами й запишіть правильне значення в `stamps`. Не можна автоматично відновити історію приблизно 40 каналів із поточної версії бота: у ній `users_db` зберігається лише в оперативній пам'яті й скидається після перезапуску.

### Поточні обмеження
- Створення акаунтів і видача паролів поки виконуються вручну через Firebase Console.
- Нарахування/списання штампів і підтвердження безкоштовної 8-ї участі мають виконуватися адміністратором після перевірки; не довіряйте значенням `stamps` або `isFree`, які надходять із браузера.
- Скретч-ефект — це візуальний елемент. Сам по собі він не підтверджує участь і не має нараховувати бонус.
- Перед відкриттям доступу всім каналам перевірте в тестовому акаунті вхід, вихід, відображення штампів і спробу читати профіль іншого UID.
